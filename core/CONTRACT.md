# Контракт core v1

Вход: `input/job.json` и `input/submissions/{submissionId}/{filename.java}`. ID работ — UUID;
одна работа содержит один файл. Схемы: [job](schemas/job.schema.json), [result](schemas/result.schema.json).

```json
{
  "contract": "integritylens.core/1",
  "runId": "00000000-0000-4000-8000-000000000001",
  "method": "jplag",
  "params": {},
  "submissions": [
    {"id": "00000000-0000-4000-8000-000000000002", "language": "java", "files": ["Main.java"]}
  ]
}
```

Пример сокращён: фактически требуется 5–50 работ. `method` — `jplag` или `structsim`.
Имена файлов — basename, исходные подпапки ZIP остаются в метаданных API.

Выход: `output/result.json` и необязательные файлы `output/artifacts/`. Корневые поля результата:
`contract`, `method`, `methodVersion`, фактические `params`, `submissions`, `pairs`, `warnings`.

- Каждая входная работа присутствует ровно один раз. Статус `ok` включает `score`, `matches`, `stats`;
  статус `failed` включает `reason` с кодом `NOT_PARSED`.
- Все `n*(n-1)/2` пар присутствуют ровно один раз, `a < b` лексикографически по UUID.
- `value` пары — число 0–1 или `null` с `reason`. `score` работы — максимум её оценённых пар;
  если таких пар нет — `null`. `matches` содержит до трёх наиболее похожих работ.
- `details` и `stats` — дополнительные данные метода. `fragments` необязательны; строки нумеруются с 1,
  обе границы включаются. Формат пары: `{"a":[1,3],"b":[2,4]}`; формат внутри match:
  `{"lines":[1,3],"withLines":[2,4]}`.
- При одинаковых входе, версии и параметрах результат повторяется. Версии настоящих инструментов
  адаптер должен записывать фактически, не использовать для них `mock-v1`.

Коды выхода CLI: `0` — результат записан, включая частично неразобранные работы; `1` — временный сбой
инструмента; `2` — неверный вход. Для Python API неверный вход вызывает `InvalidInput`.

## Мок

Оценка пары определяется SHA-256 от `mock-v1`, метода и отсортированных SHA-256 двух исходников.
Первые 32 бита переводятся в диапазон 0–1 с округлением до четырёх знаков. ID, порядок работ и номер
попытки не влияют на оценки. Мок не анализирует синтаксис или заимствования; даже одинаковые исходники
не обязаны получать 1.0. `details`/`stats` пустые, `fragments` пустые, версия — `mock-v1`.

В `params` поддержаны `mockScenario` и `delaySeconds`; воркер задаёт их из переменных окружения.
Для замены мока реализуйте адаптер с теми же входом и выходом и сохраните проверки контракта.
Тесты качества алгоритмов добавляются вместе с настоящими адаптерами.

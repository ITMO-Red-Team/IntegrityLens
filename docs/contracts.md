# Контракты API

HTTP API использует базовый путь /api. Форматы JSON, права доступа,
состояния и ошибки описаны ниже. Машиночитаемая спецификация — [openapi.yaml](openapi.yaml).
Схема хранения — [модель данных](data-model.md).

## UC-1. Регистрация и вход

Пользователь выбирает роль `teacher` или `student`. Регистрация создаёт
учётную запись; вход выполняется отдельно. Пароль хранится только как хеш,
полученный алгоритмом для паролей.

### Регистрация

`POST /api/auth/register`, `Content-Type: application/json`.

```json
{
  "fullName": "Иванов Игорь Петрович",
  "email": "i.ivanov@example.org",
  "password": "пример пароля",
  "role": "teacher"
}
```

Все поля обязательны. `fullName` — от 1 до 200 символов; строка из пробелов
не допускается. Email должен иметь корректный формат, не более 320 символов.
Пароль — 8–128 символов, без обязательных классов символов. Пробелы и регистр
пароля сохраняются. Длины строк считаются в символах Unicode.

Успех: `201` с объектом `User`. Сессионная cookie не создаётся.
Frontend переводит пользователя на страницу входа.

| Статус | Код | Условие |
|---|---|---|
| 409 | `EMAIL_ALREADY_REGISTERED` | Email занят; учётная запись не создаётся. |
| 422 | `VALIDATION_ERROR` | Не заполнено поле, неверный формат или длина. |
| 503 | `SERVICE_UNAVAILABLE` | Не удалось завершить операцию. |

Перед проверкой формата и поиском учётной записи пробелы по краям email удаляются, весь email приводится к нижнему регистру. Уникальность нормализованного email обеспечивает БД, включая одновременные регистрации.
Повтор успешного запроса регистрации возвращает `409`.

### Вход

`POST /api/auth/login` принимает `{email, password}`.

Успех: `200`, объект `User` и cookie:

```http
Set-Cookie: session=<opaque-token>; Path=/; Max-Age=86400; HttpOnly; Secure; SameSite=Lax
Cache-Control: no-store
```

Сессия действует 24 часа с момента входа; обращения не продлевают срок.
Токен непрозрачный, в БД хранится его хеш. Каждый успешный вход выдаёт новый токен.
Ответ не содержит токен в JSON. Успешный вход аннулирует прежнюю сессию из cookie этого браузера. Сессии других устройств сохраняются. Неуспешный вход сессии не меняет.

`401 INVALID_CREDENTIALS` имеет одно сообщение: «Неверный email или пароль».
Ответ не сообщает, существует ли учётная запись. Ошибки заполнения формы
возвращаются как `422 VALIDATION_ERROR`, сбой сервиса — `503 SERVICE_UNAVAILABLE`.

### Восстановление интерфейса

`GET /api/auth/me` возвращает `200 User` для действующей сессии.
При отсутствующей, неверной или истёкшей cookie — `401 AUTHENTICATION_REQUIRED`.
Срок сессии не продлевается. Ответы авторизации не кешируются.

```json
{
  "id": "34e87cc8-472b-44da-8cdc-6964cc61546a",
  "fullName": "Иванов Игорь Петрович",
  "role": "teacher"
}
```

После входа преподаватель открывает список заданий, студент — экран сдачи.
Если студент пришёл по ссылке задания, frontend сохраняет внутренний путь
при переходах на вход и регистрацию и возвращает на него после входа.
API возвращает JSON без HTTP-перенаправлений. Внешние адреса возврата не допускаются.

### Выход

`POST /api/auth/logout` завершает текущую сессию и возвращает `204` без тела.
Cookie удаляется с теми же `Path`, `Secure`, `HttpOnly`, `SameSite` и `Max-Age=0`.
При отсутствии действующей сессии также возвращается `204`: повтор выхода безопасен.

### Ошибки полей

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Проверьте заполнение полей.",
  "details": {
    "fields": [
      {"field": "email", "code": "INVALID_FORMAT", "message": "Введите корректный email."}
    ]
  }
}
```

`field` соответствует имени поля JSON. Коды: `REQUIRED`, `INVALID_FORMAT`,
`TOO_SHORT`, `TOO_LONG`, `INVALID_VALUE`. Frontend привязывает ошибку к полю
и показывает `message`. Неверные учётные данные показываются общей ошибкой формы.

## UC-2. Задание и ссылка для сдачи

Все операции доступны авторизованному преподавателю и выполняются под `/api`.
Задание принадлежит создавшему его преподавателю.

### Список заданий

`GET /api/assignments` возвращает `200 AssignmentSummary[]`.
В список входят свои неудалённые задания. Пустой список — `[]`.

```json
[
  {
    "id": "34e87cc8-472b-44da-8cdc-6964cc61546a",
    "title": "ДЗ-3. Многопоточность",
    "createdAt": "2026-11-01T09:00:00Z",
    "submissionCount": 50,
    "analysis": {"completed": 47, "failed": 2}
  }
]
```

`submissionCount` учитывает только текущие сдачи задания. История замен
и работы источников в него не входят.
`completed` — число работ, для которых завершены обязательные этапы анализа,
включая завершение с ошибкой. `failed` — число таких работ с ошибками.
Ожидающий или выполняющийся обязательный этап не считается завершённым.
Неприменимое сравнение без кандидатов завершению не мешает.

Frontend показывает `completed из submissionCount`. Ошибки показывает отдельно.
Если работы есть и все обработаны, можно показать «Готово»; при отсутствии
работ — «Нет работ». После смены ревизии прогресс может уменьшиться.

Список также используется для выбора источников. Кандидат — любое другое
неудалённое задание того же преподавателя, независимо от даты, наличия работ
и готовности анализа. Для сравнения используются его текущие сдачи.

### Создание

`POST /api/assignments` принимает:

```json
{
  "title": "ДЗ-3. Многопоточность",
  "sourceAssignmentIds": []
}
```

`title` обязателен: 1–200 символов после удаления пробелов по краям.
Название после создания изменить нельзя. Совпадающие названия допустимы.
`sourceAssignmentIds` — массив уникальных UUID; отсутствие поля означает `[]`.

Успех: `201 Assignment`. Объект содержит поля `AssignmentSummary`,
`sourceAssignmentIds` и абсолютную `submissionUrl` — ссылку на страницу сдачи
frontend с непрозрачным токеном. Этот токен отличается от токена сессии.
Ссылка не предоставляет доступ к результатам анализа.

Backend создаёт задание и связи с источниками атомарно. При ошибке источника
задание не создаётся. Повтор POST после успеха создаёт отдельное задание;
frontend блокирует повторное нажатие во время запроса.

### Получение задания и ссылки

`GET /api/assignments/{assignmentId}` возвращает `200 Assignment`.
Повторные запросы возвращают ту же `submissionUrl`. Копирование ссылки,
переход к заданию и возврат к списку выполняет frontend.

### Изменение источников

`PUT /api/assignments/{assignmentId}/sources` принимает
`{sourceAssignmentIds: UUID[]}` и возвращает `200 Assignment`.
Поле обязательно; массив полностью заменяет набор. `[]` удаляет все источники.
Название в запросе не допускается.

Ссылка сохраняется. Изменение набора увеличивает ревизию сходства и запускает
пересчёт. Повтор с тем же набором, независимо от порядка UUID, не вызывает
новый пересчёт. AI-оценки существующих сдач сохраняют актуальность.

### Ошибки

| Статус | Условие |
|---|---|
| 401 | Нет действующей сессии. |
| 403 | Пользователь не преподаватель. |
| 404 | Задание или выбранный источник недоступны: отсутствуют, удалены или принадлежат другому преподавателю. |
| 422 | Пустое или слишком длинное название, неверный UUID, повтор источника, ссылка задания на себя или неизвестное поле. |
| 503 | Сбой сохранения; операция не завершена. |

Набор источников проверяется до записи целиком. Ответ не раскрывает сведения
о чужом задании. Взаимные связи источников допустимы. Сравнение использует только прямые источники.

## UC-3. Сдача работы

Сдача доступна авторизованному студенту по ссылке задания. Токен ссылки
идентифицирует задание, сессия — студента. Студент не получает результаты анализа.

### Форма

`GET /api/submit/{token}` возвращает `200`:

```json
{
  "title": "ДЗ-3. Многопоточность",
  "teacherFullName": "Иванов Игорь Петрович",
  "canSubmit": true,
  "currentSubmission": null
}
```

`currentSubmission` содержит `{submissionId, submittedAt}` принятой текущей
сдачи либо `null`. Это позволяет восстановить подтверждение после перезагрузки
и показать время сдачи при повторном открытии ссылки.

| Состояние | canSubmit | currentSubmission |
|---|---|---|
| Первая сдача | true | null |
| Работа принята | false | Принятая сдача |
| Преподаватель сбросил попытку | true | Прежняя сдача |

При `canSubmit: false` frontend блокирует форму и сообщает, что повторная
сдача возможна после сброса преподавателем. После сброса прежняя работа
остаётся текущей до успешного приёма новой.

Без сессии API возвращает `401`; frontend переводит на вход с возвратом
к заданию. Преподавателю возвращается `403`. Неверный токен или удалённое
задание дают одинаковый `404`.

### Отправка

`POST /api/submit/{token}`, `multipart/form-data`, поле `file`.
Backend проверяет ровно один непустой файл, расширение `.java`, корректный
UTF-8 и размер не более **1 000 000 байт**. MIME-тип не заменяет проверку
содержимого. Синтаксическая корректность Java проверяется анализатором и
не является условием приёма файла.

Успех — `201`:

```json
{
  "submissionId": "34e87cc8-472b-44da-8cdc-6964cc61546a",
  "submittedAt": "2026-11-07T15:42:00Z"
}
```

Время задаёт сервер в UTC; frontend форматирует его для пользователя.
Успех означает сохранение файла и сдачи, закрытие попытки и постановку анализа
в очередь. Ожидание или ошибка анализа не отменяют приём.

Выбранное локальное имя и размер frontend показывает до отправки. Для принятой
работы используется нейтральное имя `source.java`; исходное имя не хранится
ради отображения.

### Ошибки файла

Ответ имеет формат `{code, message, details?}`.

| HTTP | code | message |
|---|---|---|
| 422 | FILE_REQUIRED | Выберите файл. |
| 422 | MULTIPLE_FILES | Можно отправить только один файл. |
| 422 | EMPTY_FILE | Файл не должен быть пустым. |
| 422 | INVALID_EXTENSION | Допускается только файл с расширением .java. |
| 422 | INVALID_ENCODING | Файл должен быть в кодировке UTF-8. |
| 413 | FILE_TOO_LARGE | Размер файла превышает 1 МБ. |
| 409 | SUBMISSION_ALREADY_ACCEPTED | Работа уже принята. |
| 503 | SERVICE_UNAVAILABLE | Не удалось принять работу. Повторите попытку. |

Ошибки валидации не расходуют попытку. При сбое сохранения сдача и задания
анализа не фиксируются в PostgreSQL, попытка остаётся открытой. Ключ объекта MinIO остаётся в очереди удаления до очистки.

При одновременной отправке двух запросов принимается только одна сдача;
второй запрос получает `409`. Повтор успешного POST также возвращает `409`.
Если ответ потерян из-за сети, frontend сначала обновляет GET формы и проверяет
`currentSubmission`, прежде чем предлагать повторную отправку.

## UC-4 и UC-5. Просмотр работ

Результаты доступны только преподавателю-владельцу задания.

### Список работ

`GET /api/assignments/{assignmentId}/submissions`.

| Параметр | Значение |
|---|---|
| `sort` | `similarity` (по умолчанию) или `ai` |
| `page` | Номер страницы с 1; по умолчанию 1 |
| `pageSize` | От 1 до 100; по умолчанию 20 |

Backend сортирует весь список по выбранной оценке по убыванию, при равенстве —
по UUID работы. Отсутствующие оценки находятся в конце. Пагинация применяется
после сортировки. Ответ содержит `items`, `page`, `pageSize`,
`total`. `total` — число текущих сдач задания до пагинации. Для пустого списка
или страницы за его пределами возвращается `200` с `items: []`.

Каждая строка содержит `submissionId`, `studentId`, `fullName`, `submittedAt`,
`similarity`, `ai`. Скрытие ФИО выполняет frontend: переключение
«Показать ФИО» не вызывает отдельного запроса. Анонимную подпись работы
frontend формирует из её идентификатора. API доступен только владельцу задания.

Сброс попытки использует `studentId` из строки и существующую ручку
`POST /api/assignments/{assignmentId}/students/{studentId}/reset`.

### Исходник

`GET /api/submissions/{submissionId}/source` возвращает сохранённый исходник
как `text/plain; charset=utf-8`. Доступны только текущие сдачи неудалённых заданий. Для заменённых сдач и сдач удалённых заданий возвращается 404; история хранится без публичного API чтения. Интерфейс показывает нейтральное имя
`source.java`; исходное имя файла для отображения не требуется.

### Сравнение пары

`GET /api/assignments/{assignmentId}/pairs/{a}/{b}` возвращает оценки
и совпавшие фрагменты двух разных работ актуального набора сравнения.
Хотя бы одна работа принадлежит текущему заданию; вторая может быть его
текущей работой или текущей работой прямого источника.

Ответ сохраняет порядок `a` и `b` из запроса. Если в БД пара хранится в
обратном порядке, backend разворачивает стороны фрагментов.

```json
{
  "a": "34e87cc8-472b-44da-8cdc-6964cc61546a",
  "b": "55dd30f0-8e99-4fea-9562-a087f2bb145e",
  "score": {"status": "ok", "value": 0.91},
  "methods": {
    "structsim": {
      "score": {"status": "ok", "value": 0.91},
      "fragments": [{"a": [8, 11], "b": [9, 12]}],
      "details": {}
    }
  }
}
```

Диапазоны Structsim — номера строк с 1, обе границы включены. Каждая запись
связывает фрагмент слева с фрагментом справа. Frontend использует индекс
записи для нумерации совпадений и синхронной прокрутки. Отдельный запрос
для клика по фрагменту не требуется. Пустой массив означает отсутствие
фрагментов; это не ошибка запроса.

AI-фрагменты `suspicious` используют другой формат: байтовые смещения UTF-8
с 0 и исключённой правой границей. Они подсвечиваются независимо от совпадений
Structsim. Backend не должен смешивать эти две системы координат.

### Открытие похожей работы как основной

Поле `assignmentId` в `SimilarWork` указывает собственное задание похожей работы.
Кнопка «Открыть как основную» переводит в это задание и запрашивает
`GET /api/assignments/{assignmentId}/submissions/{submissionId}`.
Список похожих работ и оценки рассчитываются в контексте его актуального
набора сравнения. Поэтому они могут отличаться от результатов исходного задания.

Само сравнение пары до перехода остаётся в контексте просматриваемого задания.
Если задание похожей работы удалено или сдача больше не является текущей,
открытие её как основной возвращает `404`; frontend предлагает вернуться
к исходному заданию.

## Управление заданием

### Сброс попытки

`POST /api/assignments/{assignmentId}/students/{studentId}/reset` доступен
преподавателю-владельцу. Успех — `204` без тела. Запрос открывает попытку
для студента, у которого есть текущая сдача этого задания.

Тело запроса: `{expectedSubmissionId: UUID}`. Backend атомарно сравнивает его с `current_submission_id` и открывает попытку только при совпадении. Если сдача изменилась — `409 SUBMISSION_CHANGED`; frontend обновляет список.

Сброс не удаляет сдачу, не меняет `current_submission_id`, оценки и ревизию
сходства. Они меняются после успешной повторной сдачи. Повтор сброса уже
открытой попытки возвращает `204`. Для студента без сдачи возвращается `404`.

Ошибки: `401` — нет сессии, `403` — неверная роль, `404` — недоступное задание
или нет текущей сдачи студента, `503` — сбой сохранения. Frontend запрашивает
подтверждение до отправки; отмена диалога не вызывает API.

### Удаление задания

`DELETE /api/assignments/{assignmentId}` доступен преподавателю-владельцу.
Успех — `204` без тела. Задание скрывается из списка, ссылка сдачи закрывается.
Дальнейшие запросы формы сдачи и чтения задания возвращают `404`.

Задание удаляется из наборов источников других заданий. Их ревизии сходства
обновляются, результаты пересчитываются без удалённого источника.
Работы сохраняются в истории до истечения трёх лет с момента сдачи.

Ошибки: `401`, `403`, `404` для отсутствующего или чужого задания,
`503` при сбое сохранения. Повтор удаления своего уже скрытого задания
возвращает `204`. Подтверждение удаления выполняет frontend.

Операции изменения состояния задания и попытки выполняются транзакционно.
Сдача в удалённое задание не принимается; проверка состояния повторяется
в транзакции сохранения. Повтор старого сброса после новой сдачи отклоняется по expectedSubmissionId.

## Форматы результатов

| Объект | Поля |
|---|---|
| `SubmissionRow` | `submissionId`, `studentId`, `fullName`, `submittedAt`, `similarity`, `ai` |
| `SubmissionDetail` | Поля строки, `suspicious` и `similar` |
| `SimilarWork` | `submissionId`, `assignmentId`, `assignmentTitle`, `score` |
| `Score` | `status`, `value`, необязательные `reason: {code, message}` и `comparisons: {successful, skipped}` |

`GET /api/assignments/{assignmentId}/submissions/{submissionId}` возвращает
`SubmissionDetail`. Массив `similar` упорядочен по сходству по убыванию,
при равенстве — по UUID работы. Пустой список возвращается как `[]`.
AI-фрагменты отсутствуют (`suspicious: []`), пока AI-оценка не имеет статус `ok`.
Для неготового или ошибочного Structsim `fragments: []`.

`Score.status` принимает `ok`, `pending`, `failed`, `not_applicable`.
При `ok` значение находится в [0, 1]; иначе равно `null`.
При `failed` обязательны машинный код причины и сообщение для пользователя.

Сходство ожидает завершения прогона. Если сама работа не разобрана, она получает
`failed` с причиной `NOT_PARSED`. У корректной работы значение — максимум по успешным
парам; ошибки разбора других файлов не скрывают успешные сравнения.

Завершённая агрегированная оценка разобранной работы содержит `comparisons`:
`{successful, skipped}` — количество успешных и пропущенных пар. При `skipped > 0`
frontend показывает «Пропущено сравнений: N» рядом с оценкой и на странице работы.
Этот признак не переводит корректную работу в ошибку и не увеличивает счётчик ошибок.

Если успешных пар нет (включая случай, когда все остальные файлы не разобрались),
корректная работа получает `not_applicable`, `value: null`, а не нулевое сходство.
Без кандидатов также возвращается `not_applicable`. У неготовой или неразобранной
работы, у оценки отдельной пары и у AI поля `comparisons` нет.
Сбой всего прогона остаётся `failed` для всех его работ. Ошибка пары сохраняется
и показывается при открытии этой пары; запись об ошибке другого файла не удаляется.
Оценки методов независимы: ошибка или ожидание одного метода не скрывает результат другого.

## Общие ошибки HTTP

Тело ошибки: `{code, message, details?}`. `code` предназначен для логики
frontend, `message` — для отображения пользователю. Ответ не включает
пароли, токены сессии, трассировку исключений и сведения о чужих ресурсах.

| HTTP | Значение |
|---|---|
| 401 | Нет действующей сессии или неверные учётные данные при входе |
| 403 | Роль не допускает операцию |
| 404 | Ресурс или ссылка недоступны, включая чужие и удалённые задания |
| 409 | Email занят, сдача уже принята или текущая сдача изменилась перед сбросом |
| 413 | Превышен размер файла |
| 422 | Некорректные поля, UUID, параметры запроса или содержимое файла |
| 503 | Операция не завершена из-за сбоя сервиса |

Проверка обязательных полей и параметров выполняется на backend независимо
от проверки формы в браузере. Параметры пагинации вне допустимых границ дают
`422`; корректный номер страницы за пределами списка — `200` с пустым массивом.

## Контракты воркеров

Локальный запуск. Воркер читает job.json, загружает файлы из MinIO в рабочий каталог и проверяет result.json перед записью в PostgreSQL.

STRUCTSIM  integritylens.core/3

Вход  {contract, runId, revision, method, methodVersion, params, submissions[]}

Работа  {id, language: "java", files: [filename], scope}. scope — target или source.

Файл  input/submissions/{id}/{filename}.

Выход  Поля запуска, pairs[] и failedInputs[]. Пара — {a, b, value, details, fragments, reason?}.

Полнота  По одной записи на пару a < b с хотя бы одной целевой работой. Для n целевых работ и m источников — n × (n − 1) / 2 + n × m пар. При 0 парах прогон пропускается.

Фрагмент  {"a":[4,12],"b":[7,15]}. Строки с 1, обе границы включены.

Ошибка входа  failedInputs содержит ровно по одной записи {id, reason: {code: "NOT_PARSED"}}
на неразобранную работу из снимка, включая источники. Остальные работы разобраны.
ID уникальны и принадлежат входу. Ошибки входов сохраняются в analysis_run_inputs.error_code.

Ошибка пары  value: null, fragments: [], reason.code обязателен. Все пары с
неразобранной работой получают NOT_PARSED. Воркер проверяет согласованность
failedInputs и пар до публикации; нельзя пометить чужую работу ошибочной по одному лишь сбою её пары.

AI  integritylens.ai/1

Вход  {contract, runId, methodVersion, params, inputFiles[]}

Файл  {submissionId, path}. path относительно рабочего каталога. Инструмент обрабатывает один или несколько файлов независимо.

Выход  Поля запуска и files[]. Ровно один {submissionId, status, score, suspicious, reason?} на входной файл.

Фрагмент  {"startIndex":123,"endIndex":456,"confidence":0.81}. Смещения в байтах UTF-8 с 0, правая граница исключена. Обе границы лежат на границах символов.

Оценки  score — оценка всей работы, confidence — фрагмента. Обе в [0, 1]. При ok список suspicious может быть пустым.

Ошибка файла  status: "failed", score: null, suspicious: [], reason.code обязателен.

Одинаковые файлы, версия метода и параметры дают одинаковые оценки. Рабочие файлы и отчёты удаляются после прогона.


## Прогресс анализа

Работа считается завершённой, когда обе оценки находятся в терминальном состоянии: ok, failed или not_applicable. Пока хотя бы одна pending, работа остаётся в анализе. В число ошибок входит завершённая работа с хотя бы одной оценкой failed. Каждый метод отображается независимо; общего числа поверх Structsim и AI нет.

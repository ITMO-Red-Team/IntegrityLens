Бизнес требования
БТ-1. Сокращение трудозатрат на выявление несамостоятельных работ.
Система должна сократить трудозатраты преподавателя на выявление работ, выполненных студентом не самостоятельно (заимствование у других студентов, генерация с помощью ИИ, выполнение другим лицом).
Мера: доля работ задания, которые преподавателю нужно открыть, чтобы выявить 70% несамостоятельных работ.
Целевое значение: не более 35% (при ручной проверке в случайном порядке около 70%).
________________
Бизнес-правила
БП-1. Конфиденциальность результатов. 
Результаты анализа и файлы работ доступны только преподавателю, создавшему задание. Студентам они недоступны.


БП-2. Однократная отправка работы.
Студент может отправить работу по заданию только один раз. Повторная отправка возможна только после сброса попытки преподавателем.


БП-3. Локальная обработка данных.
Работы не передаются третьим лицам и внешним сервисам. Все методы анализа, включая детектор ИИ, работают локально.


БП-4. Хранение истории работ.
Работы студента хранятся 3 года независимо от удаления заданий.
________________
Пользовательские требования
Преподаватель
ПТ-1. Ранжированный список работ.
Я, как преподаватель, хочу видеть список работ задания, отсортированный по убыванию общей оценки риска, чтобы начать проверку с наиболее вероятных случаев несамостоятельного выполнения.


ПТ-2. Составляющие оценки.
Я, как преподаватель, хочу видеть для каждой работы оценки сходства и ИИ-генерации, чтобы понимать, чем вызвана общая оценка.


ПТ-3. Наиболее похожие работы.
Я, как преподаватель, хочу при открытии работы видеть список наиболее похожих на нее работ, чтобы найти источник заимствования.


ПТ-4. Параллельный просмотр.
Я, как преподаватель, хочу видеть две работы рядом на одном экране, чтобы самостоятельно оценить их сходство.


ПТ-5. Подсветка совпадений.
Я, как преподаватель, хочу видеть подсвеченные совпадающие фрагменты в двух работах, чтобы быстро найти заимствованные участки.


ПТ-6. Создание задания.
Я, как преподаватель, хочу создать задание и получить ссылку для сдачи, чтобы студенты сами загружали работы.


ПТ-7. Задания-источники.
Я, как преподаватель, хочу выбрать свои прошлые задания в качестве источников, чтобы находить заимствования из работ прошлых потоков.


ПТ-8. Сброс попытки.
Я, как преподаватель, хочу сбросить попытку сдачи студента, чтобы он мог отправить работу повторно в обоснованном случае.


ПТ-9. Удаление задания.
Я, как преподаватель, хочу удалить задание, чтобы убрать его из своего списка.


ПТ-10. Анонимный просмотр.
Я, как преподаватель, хочу видеть работы без ФИО студентов и раскрывать ФИО по желанию, чтобы оценивать работы непредвзято.
Студент
ПТ-11. Отправка работы.
Я, как студент, хочу отправить свою работу по ссылке задания, чтобы сдать ее преподавателю.

Функциональные требования
0. Пользователи и доступ
ФТ-0.1. Регистрация.
Система предоставляет открытую регистрацию с указанием ФИО, email, пароля и роли (студент или преподаватель).


ФТ-0.2. Аутентификация.
Система предоставляет вход по email и паролю. При неверных данных выводится ошибка.


ФТ-0.3. Права доступа.
Преподаватель видит только свои задания, работы по ним и результаты их анализа. Студент может только сдавать работы.




________________
1. Задания
ФТ-1.1. Создание задания.
Преподаватель создаёт задание, указывая его название.


ФТ-1.2. Ссылка для сдачи.
При сохранении задания система генерирует уникальную ссылку для сдачи и показывает ее преподавателю.


ФТ-1.3. Задания-источники. При создании или редактировании задания преподаватель может выбрать в качестве источников свои прошлые задания.


ФТ-1.4. Сброс попытки. Преподаватель может сбросить попытку сдачи конкретного студента, после чего тот может отправить работу повторно.


ФТ-1.5. Удаление задания. Преподаватель может удалить задание. Оно пропадает из его списка, а работы остаются в истории по БП-4.


________________
2. Сдача работ
ФТ-2.1. Отправка.
Авторизованный студент загружает один файл по ссылке задания. Повторная отправка блокируется, если попытку не сбросил преподаватель.


ФТ-2.2. Валидация.
До сохранения файла система проверяет его на соответствие ограничениям. При нарушении сохранение блокируется, и пользователь видит конкретную причину.


ФТ-2.3. Подтверждение.
После успешного сохранения студент видит подтверждение того, что работа принята.
________________
3. Анализ работ
ФТ-3.1. Запуск.
Каждая новая работа автоматически анализируется в фоновом режиме.


ФТ-3.2. Оценка сходства.
Система сравнивает работу со всеми работами текущего задания и заданий-источников и рассчитывает для каждой пары оценку от 0.0 до 1.0.


ФТ-3.3. Оценка ИИ-генерации.
Система рассчитывает для работы оценку вероятности ИИ-генерации от 0.0 до 1.0.



ФТ-3.5. Общая оценка.
Система рассчитывает для работы общую оценку риска от 0.0 до 1.0 на основе оценок сходства и ИИ-генерации.


ФТ-3.6. Ошибки.
При сбое анализа система вместо оценки записывает и показывает причину ошибки, понятную для пользователя.
________________
4. Интерфейс преподавателя
ФТ-4.1. Список работ.
Список работ задания содержит анонимный идентификатор работы, общую оценку и две составляющие. По умолчанию он отсортирован по убыванию общей оценки. Оценки появляются по мере готовности.


ФТ-4.2. Похожие работы.
При открытии работы система показывает список наиболее похожих на нее работ. Для каждой указаны анонимный идентификатор, оценка сходства и название задания, к которому она относится.


ФТ-4.3. Параллельный просмотр.
При выборе похожей работы система показывает обе работы в двух панелях на одном экране вместе с их оценкой сходства.


ФТ-4.4. Подсветка и синхронизация.
Совпадающие фрагменты подсвечиваются в обеих панелях. При клике на фрагмент в одной панели вторая прокручивается к соответствующему фрагменту.


ФТ-4.5. Анонимизация.
По умолчанию во всех интерфейсах преподавателя ФИО студентов скрыты и заменены анонимными идентификаторами. По нажатию кнопки преподаватель раскрывает ФИО сразу для всех работ задания.
________________
5. Удаление данных
ФТ-5.1. Срок хранения.
Через 3 года после сдачи работа и связанные с ней результаты анализа безвозвратно удаляются.
________________
Нефункциональные требования
1. Безопасность
НФТ-1.1. Хранение паролей.
Пароли не хранятся, только в виде хеша, полученного алгоритмом для паролей.


НФТ-1.2. Изоляция данных.
Доступ к работам и результатам анализа проверяется на уровне API: преподаватель получает только данные своих заданий.


НФТ-1.3. Локальная обработка. Компоненты анализа не обращаются к внешним сетевым сервисам.
2. Технические ограничения
НФТ-2.1. Язык.
Система анализирует только работы на Java.


НФТ-2.2. Файл работы.
Один файл, расширение .java, размер не более 1 МБ, кодировка UTF-8.
3. Производительность и воспроизводимость
НФТ-3.1. Время анализа.
Анализ задания из 50 работ завершается не позже чем через 10 минут после загрузки последней работы. Число источников и оборудование ещё не определены.


НФТ-3.2. Детерминизм.
Одинаковые входные данные при одинаковой версии методов дают одинаковые оценки.


4. Развертывание
НФТ-4.1. Воспроизводимость окружения.
Все компоненты собираются и запускаются автоматически по инструкции на чистой ОС, где из зависимостей есть только Docker.
UC-1. Зарегистрироваться и войти в систему
Предыстория. Преподаватель впервые хочет использовать систему для проверки потока ДЗ; студент получил ссылку на задание и должен иметь учётную запись, чтобы сдать работу.
Участники: Пользователь (преподаватель или студент).
Предусловия: пользователь не авторизован.
Основной сценарий (регистрация и вход):
1. Пользователь открывает страницу регистрации.
2. Пользователь вводит ФИО, email, пароль и выбирает роль: студент или преподаватель.
3. Система проверяет заполненность полей и уникальность email.
4. Система сохраняет пароль только в виде хеша, полученного алгоритмом для паролей (НФТ-1.1), и создаёт учётную запись.
5. Пользователь вводит email и пароль на странице входа.
6. Система проверяет учётные данные и открывает стартовый экран по роли: преподавателю — список заданий, студенту — экран сдачи (или страницу задания, если вход начат со ссылки).
Альтернативные сценарии:
* А1. Пользователь уже зарегистрирован. Переходит сразу к шагу 5.
* А2. Вход начат со ссылки задания. Студент, открывший ссылку без авторизации, перенаправляется на вход; после шага 6 система возвращает его на страницу этого задания.
Негативные сценарии:
* Н1. Email уже занят. Система не создаёт учётную запись и сообщает, что email уже зарегистрирован; предлагает перейти ко входу.
* Н2. Не заполнено обязательное поле или некорректный формат email. Система подсвечивает поле и сообщает причину.
* Н3. Неверный email или пароль. Система выводит ошибку (ФТ-0.2), не уточняя, какое из полей неверно; пользователь остаётся на странице входа.
Постусловия: создана учётная запись с ролью; пользователь авторизован.


UC-2. Создать задание и получить ссылку для сдачи
Предыстория. Преподаватель выдаёт новое ДЗ по Java потоку из ~50 студентов. Он подозревает, что часть студентов может списать у прошлого потока, поэтому хочет сравнивать работы и с прошлогодним заданием.
Участники: Преподаватель, Система.
Предусловия: преподаватель авторизован (UC-1).
Основной сценарий:
1. Преподаватель в списке заданий нажимает «Создать задание».
2. Система открывает форму: поле «Название» и список прошлых заданий преподавателя для выбора в качестве источников.
3. Преподаватель вводит название.
4. Преподаватель отмечает одно или несколько прошлых заданий как источники (ФТ-1.3).
5. Преподаватель сохраняет задание.
6. Система создаёт задание, генерирует уникальную ссылку для сдачи и показывает её с кнопкой копирования (ФТ-1.2).
7. Преподаватель копирует ссылку и передаёт её студентам вне системы.
Альтернативные сценарии:
* А1. Источники не нужны или прошлых заданий нет. Преподаватель пропускает шаг 4; сравнение идет только внутри текущего задания.
* А2. Редактирование источников. Преподаватель открывает существующее задание, меняет набор заданий-источников и сохраняет. Ссылка не меняется. Уже рассчитанные работы пересчитываются с учётом нового набора.
* А3. Повторное получение ссылки. Преподаватель в любой момент открывает задание и копирует ту же ссылку.
Негативные сценарии:
* Н1. Название пустое. Система не сохраняет задание и подсвечивает поле.
* Н2. Попытка выбрать чужое задание. В списке источников показываются только задания текущего преподавателя; запрос API с чужим ID отклоняется (НФТ-1.2).
Постусловия: задание создано и принадлежит преподавателю; у него есть уникальная ссылка; связи с заданиями-источниками сохранены.


UC-3. Отправить работу по ссылке задания
Предыстория. Студент выполнил ДЗ на Java и получил от преподавателя ссылку на задание. Ему нужно сдать решение до дедлайна и убедиться, что работа принята.
Участники: Студент, Система, Модуль анализа.
Предусловия: задание существует и не удалено; у студента есть ссылка.
Основной сценарий:
1. Студент открывает ссылку задания.
2. Система проверяет, что студент авторизован, и показывает название задания и форму загрузки с ограничениями: один файл .java, до 1 МБ, UTF-8.
3. Система проверяет, что у студента нет принятой работы по этому заданию (БП-2).
4. Студент выбирает файл и нажимает «Отправить».
5. Система валидирует файл до сохранения: расширение .java, размер ≤ 1 МБ, кодировка UTF-8 (ФТ-2.2, НФТ-2.2).
6. Система сохраняет работу, связывает её со студентом и заданием, фиксирует время сдачи (отсчёт срока хранения по ФТ-5.1).
7. Система показывает подтверждение «Работа принята» (ФТ-2.3).
8. Система ставит работу в очередь анализа.
Альтернативные сценарии:
* А1. Студент не авторизован. Система перенаправляет на вход или регистрацию, затем возвращает к шагу 2.
* А2. Попытка сброшена преподавателем. Предыдущая работа есть, но попытка сброшена: система разрешает отправку, сценарий продолжается с шага 4. Новая работа заменяет прежнюю в анализе задания.
Негативные сценарии:
* Н1. Работа уже отправлена. Система блокирует форму и сообщает, что работа уже принята, повторная сдача возможна только после сброса попытки преподавателем.
* Н2. Неверное расширение. Сохранение блокируется: «Допускается только файл с расширением .java».
* Н3. Файл больше 1 МБ. Сохранение блокируется: «Размер файла превышает 1 МБ».
* Н4. Кодировка не UTF-8. Сохранение блокируется: «Файл должен быть в кодировке UTF-8».
* Н5. Выбрано несколько файлов или файл пустой. Сохранение блокируется с указанием причины.
* Н6. Ссылка недействительна или задание удалено. Система сообщает, что задание недоступно для сдачи.
* Н7. По ссылке зашёл пользователь с ролью «Преподаватель». Система сообщает, что сдача доступна только студентам.
* Н8. Сбой сохранения. Система сообщает, что работа не принята, и предлагает повторить; попытка не считается использованной.
UC-4. Просмотреть ранжированный список работ задания
Предыстория. Дедлайн прошёл, сдано 50 работ. У преподавателя есть время внимательно проверить лишь треть. Он хочет начать с работ, где вероятность несамостоятельного выполнения выше, и понимать, чем вызван риск (БТ-1: найти 70% несамостоятельных работ, открыв не более 35%).
Участники: Преподаватель, Система.
Предусловия: преподаватель авторизован; в задании есть хотя бы одна работа.
Основной сценарий:
1. Преподаватель открывает задание из своего списка.
2. Система проверяет, что задание принадлежит преподавателю (НФТ-1.2).
3. Система показывает список работ: анонимный идентификатор, общая оценка риска, оценки сходства и ИИ-генерации (ФТ-4.1, ПТ-2).
4. Список по умолчанию отсортирован по убыванию общей оценки (ПТ-1).
5. Преподаватель просматривает составляющие у верхних работ, чтобы понять, чем вызван высокий риск.
6. Преподаватель открывает работу с наибольшим риском.
Альтернативные сценарии:
* А1. Анализ части работ ещё не завершён. Такие работы показываются со статусом «Анализ» без оценок и располагаются в конце списка; по мере готовности оценки появляются и список перестраивается (ФТ-4.1).
* А3. Сортировка по составляющей. Преподаватель сортирует список по оценке сходства или ИИ-генерации; повторный выбор возвращает сортировку по общей оценке.
* А4. Преподаватель хочет видеть авторов.
Негативные сценарии:
* Н1. Ошибка анализа работы. Вместо оценки показывается понятная причина (ФТ-3.6), например «Не удалось разобрать файл как Java-код»; работа в конце списка.
* Н2. Попытка открыть чужое задание (подстановка ID в URL/API). Система возвращает отказ в доступе, данные не раскрываются (ФТ-0.3, НФТ-1.2).
* Н3. В задании нет работ. Система показывает пустой список и ссылку для сдачи.
Постусловия: преподаватель видит актуальный порядок проверки; система не выносит вердикт — оценка служит только основанием для ручной проверки.


UC-5. Найти источник заимствования и сравнить работы
Предыстория. У работы A-17 оценка сходства 0.91. Преподаватель должен сам убедиться, что совпадение содержательное (а не шаблонный код из условия), найти, у кого заимствовано — в текущем потоке или в прошлом, — и принять решение вне системы.
Участники: Преподаватель, Система.
Предусловия: выполнен UC-4; у выбранной работы рассчитана оценка сходства.
Основной сценарий:
1. Преподаватель открывает работу из ранжированного списка.
2. Система показывает код работы и список наиболее похожих работ по убыванию сходства: анонимный идентификатор, оценка сходства, название задания (текущее или источник) (ФТ-4.2, ПТ-3).
3. Преподаватель выбирает работу с наибольшим сходством.
4. Система открывает две панели рядом: слева исходная работа, справа выбранная; над ними оценка сходства пары (ФТ-4.3, ПТ-4).
5. Система подсвечивает совпадающие фрагменты в обеих панелях; соответствующие фрагменты связаны (ПТ-5).
6. Преподаватель кликает фрагмент в левой панели.
7. Система прокручивает правую панель к соответствующему фрагменту и выделяет его (ФТ-4.4).
8. Преподаватель оценивает характер совпадения и решает, проводить ли дополнительное ревью; решение принимается вне системы.
Альтернативные сценарии:
* А1. Источник — работа прошлого потока. В списке у похожей работы указано название задания-источника; сравнение выполняется так же, ФИО автора прошлой работы скрыто тем же правилом анонимизации.
* А2. Клик во второй панели. Синхронизация работает в обратную сторону: прокручивается левая панель.
* А3. Последовательная проверка кандидатов. Преподаватель возвращается к списку похожих работ и выбирает следующую (шаг 3).
* А4. Преподаватель открывает работу из правой панели как основную. Система показывает уже её список похожих работ (шаг 2) — так ищется цепочка заимствований.

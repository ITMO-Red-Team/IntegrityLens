# research

Директория проведения исследования.

Разворачивать MLFlow не хочется (это из пушки по воробьям), поэтому все результаты должны быть сохранены здесь в поддиректории `results/`.

Подниматься в Docker необязательно, так как этим модулем никто не пользуется. Для этой директории нужно выбрать структуру и придерживаться её, чтобы каши не было.

Пожелания:

1. Python
2. Разделить всё на эксперименты
3. Каждый эксперимент должен иметь интерпретацию и вывод

## Структура

Выбрана такая, начиная с эксперимента `two`. Эксперимент — самодостаточная
директория: свой вопрос, своё окружение, свои результаты. Читается целиком,
без оглядки на соседние эксперименты. Внешние инструменты в неё не входят —
они общие и лежат в [`tools/`](../tools/README.md).

```
research/
  <эксперимент>/            — один каталог на эксперимент
    README.md               — вопрос, гипотезы, протокол, оговорки
    pyproject.toml          — свой uv-проект: у экспериментов разные зависимости
    src/<пакет>/
      config.py             — версии, источники данных, параметры прогонов
      paths.py              — пути
      containers.py         — запуск контейнеров
      doctor.py             — проверка окружения
      stages/               — стадии sNN_*, каждая запускается отдельно и
                              идемпотентна: падение на s30 не заставляет
                              перезапускать s00
    data/                   — сырые входные данные, вне git (качаются стадией s00)
    work/                   — промежуточные выгрузки, вне git
    results/                — в git:
      scores/               — таблицы оценок и разметки
      tables/               — таблицы отчёта
      figures/              — графики
      REPORT.md             — интерпретация и вывод
```

Правила:

1. **Версии прибиты.** Внешний инструмент запускается только из образа с
   фиксированной версией и, где возможно, с проверкой контрольной суммы.
   Иначе результат невоспроизводим.
2. **Данные не в git**, но их происхождение — в `config.py`: адрес, контрольная
   сумма, ожидаемые размеры разметки. Стадия `s00` обязана их сверять.
3. **Результаты в git**, в `<эксперимент>/results/`. Рядом с кодом, который их
   породил, а не в общей свалке. Всё, что можно перегенерировать за минуты и
   что весит мегабайты, туда не кладётся — это `work/`.
4. **Проверка окружения — код, а не инструкция.** `uv run doctor` должен
   падать раньше, чем эксперимент встанет на полпути, и проверять не
   «инструмент запустился», а «инструмент выдал ожидаемые числа на фикстуре».
   Разница не теоретическая: JPlag на образе без JDK запускается нормально и
   молча не разбирает ни одного файла.
5. **Внешние инструменты — не часть эксперимента.** Образ с прибитой
   версией, документация и фикстуры каждого инструмента лежат в
   [`tools/<инструмент>/`](../tools/README.md) и переиспользуются
   экспериментами. Эксперимент прибивает в `config.py` версию, на которой
   получены его числа, но инструментом не владеет: JPlag — baseline, Semgrep —
   шаг 1 метода, и ни то ни другое не принадлежит одному эксперименту.
6. **Интерпретация и вывод** — в `<эксперимент>/results/REPORT.md`.
   Отрицательный результат тоже результат и записывается как есть.

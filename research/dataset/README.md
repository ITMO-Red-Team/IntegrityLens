# dataset

Валидационный датасет: размеченные работы на Java, на которых считается
бизнес-метрика БТ-1 ([issue #28](https://github.com/ITMO-Red-Team/IntegrityLens/issues/28)).

Это исключение из правила «данные не в git» из [`research/README.md`](../README.md):
датасет маленький, и разметка должна лежать рядом с кодом, который её получил.

## Метрика

Работы задания сортируются по убыванию оценки риска. Метрика — доля работ,
которые надо открыть сверху, чтобы среди них оказалось 70% несамостоятельных.
Цель — не больше 0.35. Считается по каждому заданию отдельно и усредняется.

```bash
python3 research/dataset/src/metric.py scores.csv
```

`scores.csv` — столбцы `assignment_id`, `work_id`, `score`; пустой `score`
значит «анализ не удался», такая работа уходит в конец списка. При равных
оценках честные работы считаются стоящими выше.

## Раскладка

```
assignments.csv                          задания
labels.csv                               разметка работ
pairs.csv                                разметка пар
assignments/<id>/statement.md            условие и особенности задания
assignments/<id>/works/<uuid>/Main.java  работа
ai/<id>/<n>.java                         работы, написанные ИИ, до раскладки
src/                                     сборка и проверка
```

Работа — один файл `.java` в UTF-8, 30–300 строк, содержимое не менялось.
Имя директории — случайный UUID: по нему метку не угадать.

### labels.csv

| столбец | значение |
|---|---|
| `label` | 1 — несамостоятельная, 0 — честная |
| `kind` | `honest`, `plagiarism`, `ai`; в задании-источнике ещё `donor` — работа, с которой списали |
| `role` | для списанных: `unknown` — кто у кого списал, в источнике не указано; `copy` — списана с работы прошлого потока |
| `case_id` | кейс списывания; в кейсе все работы, связанные списыванием |
| `source_work_id` | для `copy` — работа-источник в задании прошлого потока |
| `obfuscation` | вид маскировки, если известен из источника, иначе `unknown` |
| `label_source` | откуда метка, см. ниже |
| `origin` | исходный набор, версия, задача, id решения |
| `lines`, `sha256` | размер и контрольная сумма файла |

В кейсе внутри одного потока несамостоятельными считаются все работы, включая
ту, с которой списали: направление по коду не определить, преподаватель
открывает обе. У работы `donor` из прошлого потока `label = 0`.

### pairs.csv

Метки пар, перенесённые из источника и добавленные при ручной проверке.
Покрывают малую часть пар задания: пара без строки — пара без метки.

## Откуда метки

Источник — ConPlag: пары решений с соревнований Codeforces, размеченные
авторами набора как «плагиат / не плагиат». Берётся версия `version_1` — как
сдано, с личными шаблонами участников.

Метка на работу выводится из меток на пары:

1. Размеченные пары-плагиаты склеиваются в кейсы (связные компоненты).
2. Работы, совпадающие с точностью до пробелов, попадают в один кейс
   (`label_source = identical`). Так в a01 нашлась работа, побайтно равная
   списанной, но стоявшая в ConPlag только в паре «не плагиат».
3. Кейс берётся целиком или не берётся: работа без своей пары — не кейс.
4. Остальные работы считаются честными. В ConPlag размечены не все пары,
   поэтому пары без метки, которые JPlag 6.3.0 оценил не ниже 0.8 на сырой или
   на очищенной от шаблонов версии, просмотрены вручную; решения записаны в
   `src/spec.py` (`REVIEWS`) и в `pairs.csv` (`label_source = manual`).
   Просмотрено 7 пар: 3 признаны списыванием, 4 — независимыми решениями.
5. Для заданий-источников направление списывания назначено: какая из двух
   работ пары уходит в прошлый поток, выбирается случайно.

## Ограничения

- Честность работы — отсутствие известного списывания, а не доказанная
  самостоятельность. Ручная проверка идёт по кандидатам от JPlag: списывание,
  которое JPlag не видит и которое не размечено в ConPlag, осталось бы в честных.
- Это решения с соревнований, а не учебные работы: короткие алгоритмические
  задачи, у многих свой шаблон ввода-вывода.
- Вид маскировки и направление списывания в ConPlag не размечены.
- «Прошлый поток» получен разбиением решений одной задачи на два задания, а не
  из настоящих двух потоков.
- ИИ-работы написаны одной моделью двумя запросами; их правильность не
  проверялась, проверено только, что они компилируются.

## Пересборка и проверка

Нужен Python 3.10+, без зависимостей. Архив ConPlag скачивается в `data/`,
адрес и контрольная сумма — в `src/sources.py`.

```bash
python3 research/dataset/src/build.py
```
```
a01: работ 50 — честных 36, списанных 12 в 5 кейсах (размеры [3, 3, 2, 2, 2]), ИИ 2; прошлый поток 0; в источнике решений 70, кейсов 6, не прошли по размеру/кодировке 1, честных доступно 47
...
a05: работ 50 — честных 34, списанных 14 в 7 кейсах (размеры [5, 2, 2, 2, 2, 2, 2]), ИИ 2; прошлый поток 25; в источнике решений 112, кейсов 16, не прошли по размеру/кодировке 3, честных доступно 61
...
```

```bash
python3 research/dataset/src/check.py
```
```
ок: заданий 8, работ 385 (честных 268, списанных 101, ИИ 16), в заданиях-источниках 50, пар 287
```

Отбор зависит только от исходного архива, `src/spec.py` и файлов в `ai/`:
повторная сборка даёт те же файлы и те же UUID.

Для двух оставшихся команд нужны JDK 25 и
`jplag-6.3.0-jar-with-dependencies.jar` (сумма — в `tools/jplag/jplag.Dockerfile`).

Кандидаты на ручную проверку по задаче ConPlag; падает, если есть пара без решения:

```bash
python3 research/dataset/src/jplag.py review <jar> 1
```
```
77ec956f ac8ef97c {'version_1': 1.0, 'version_2': 1.0} уже в одном кейсе
5af25bd7 ac8ef97c {'version_1': 0.825, 'version_2': 0.825} уже в одном кейсе
1a31f5cb 51019113 {'version_2': 0.82} решение есть в spec.REVIEWS
задача 1: пар без метки с оценкой >= 0.8: 3, без решения: 0
```

Контрольный прогон: оценка риска работы — наибольшее сходство JPlag с другой
работой задания или задания-источника. ИИ-работы таким способом не ищутся,
поэтому это оценка снизу для системы без детектора ИИ.

```bash
python3 research/dataset/src/jplag.py scores <jar> scores.csv
python3 research/dataset/src/metric.py scores.csv
```
```
задание  работ  несамост.  открыть  случайно  цель
a01         50         14     0.28      0.68  да
a02         50         16     0.52      0.72  нет
a03         50         14     0.20      0.68  да
a04         50         16     0.28      0.72  да
a05         50         16     0.56      0.72  нет
a06         50         15     0.44      0.70  нет
a07         50         16     0.38      0.72  нет
a08         35         10     0.20      0.65  да
```

Наилучшее возможное значение — 70% несамостоятельных, делённые на число работ:
для a01 это 10 из 50, то есть 0.20.

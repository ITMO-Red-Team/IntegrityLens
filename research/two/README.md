# Эксперимент 2: structsim против JPlag

**Вопрос.** Насколько хорошо метод структурного сходства
[`structsim`](../../tools/structsim/README.md) отличает плагиат от
неплагиата по сравнению с [`JPlag`](../../tools/jplag/README.md) — стандартным
детектором на Greedy String Tiling — и значима ли разница.

Итоги, интерпретация и вывод — в [`results/REPORT.md`](results/REPORT.md).
Коротко: на коде без заготовок structsim значимо лучше JPlag (AUC 0.964
против 0.940). На коде как есть он не лучше JPlag по умолчанию и значимо
хуже JPlag с метрикой `max` (0.855 против 0.909). Причина — заготовка
участника, которая размывает симметричные меры structsim.

## Гипотезы

- **H1.** AUC `structsim` (`COMBINED`) выше AUC JPlag с настройками по
  умолчанию на обеих версиях ConPlag, и разница значима.
- **H2.** Преимущество держится против JPlag в других штатных конфигурациях
  (`--normalize`, `--match-merging`, метрика `max`) и против лучшей точки
  кривой по `-t` — то есть не объясняется тем, что baseline не настроен.
- **H3.** `contrast-z` (шаг 4, сравнение с фоном задачи) лучше `COMBINED`.
- **H4.** Ошибки инструментов расходятся, и их комбинация, обученная на train,
  даёт на test AUC выше каждого по отдельности.

## Данные

**ConPlag** — плагиат на Codeforces, Java. Slobodkin & Sadovnikov, FRUCT 33,
CC BY 4.0, [Zenodo 7332491](https://zenodo.org/records/7332491).

- 911 размеченных пар из 21 задачи: 251 плагиат, 660 не плагиат; 975 решений;
- две версии: **as-is** — решения как есть, и **template-free** — общий код
  участника (быстрый ввод, утилиты) удалён вручную авторами датасета;
- сплит авторов: 230 пар train, 681 test.

Сравнение идёт на Java, то есть на поле JPlag: кросс-языковые пары, ради
которых structsim и сделан, JPlag не умеет в принципе. Это граница baseline,
а не его проигрыш, и в этом эксперименте не проверяется.

## Протокол

Оба инструмента запускаются **на наборе задачи** — всех её решениях сразу, — а
метрики считаются по 911 размеченным парам. Для JPlag это просто дешевле
(оценка пары от остальных решений не зависит), для `contrast-z` обязательно:
фон пары — сходство каждого из двух решений с остальными решениями задачи.

| Стадия | Что делает |
|---|---|
| `s00_fetch_data` | качает ConPlag, сверяет MD5 и разметку, собирает `pairs.csv` и наборы задач |
| `s10_run_jplag` | 3 конфигурации + 6 точек кривой по `-t` × 21 задача × 2 версии |
| `s20_run_structsim` | шаги 1–4 structsim на всех 31 770 парах наборов обеих версий |
| `s30_metrics` | AUC с ДИ, PR-AUC, F1 / P / R на test с порогом от train, доля нулей |
| `s40_stats` | DeLong и парный бутстрэп разницы AUC — по парам и по задачам |
| `s50_analysis` | разбор по задачам, кривая по `-t`, расхождения, H4, время, графики |

### Конфигурации JPlag

| Имя | Ключи | Зачем |
|---|---|---|
| `default` | — (`-t 9`) | головной baseline: без подстройки под набор, как и structsim |
| `normalize` | `--normalize` | нормализация меток Java |
| `match-merging` | `--match-merging` | штатный ответ JPlag на запутывание кода |
| `t03` … `t15` | `-t 3, 5, 7, 11, 13, 15` | кривая чувствительности по порогу длины совпадения |

У каждой — обе метрики JPlag: `avg` (симметричная, головная) и `max`
(относительно более короткой программы). Все прогоны идут с `--csv-export
--cluster-skip --overwrite`.

`--base-code` не используется: ключ ждёт одну заготовку на весь набор, а в
ConPlag заготовка у каждого участника своя. Что будет без заготовок, показывает
версия template-free — там они убраны вручную, точнее любой автоматики.

### Метрики и статистика

- **AUC** по всем общим парам — основная; **PR-AUC** — положительных 27.5 %, и
  ROC на перекосе льстит обоим; **F1, P, R** на test с порогом, максимизирующим
  F1 на train; **доля оценок ровно 0.0** у плагиата — у JPlag это чистый
  промах, который никакой порог не спасёт.
- Сравнение **парное**: обе оценки на одних и тех же парах. Разница AUC
  проверяется тестом **DeLong** и **парным бутстрэпом** (10 000 повторов,
  зерно в `config.py`), p-значения поправлены по Холму.
- Бутстрэп считается дважды: **по парам** и **по задачам** (кластерный). Пары
  одной задачи не независимы — одно решение входит в несколько пар, задачи
  разной трудности, — и бутстрэп по парам даёт слишком узкий интервал.
- Пары, которые не оценил хотя бы один инструмент, исключаются из всех метрик
  версии, и их число отчитывается.

## Запуск

Нужны Docker и [uv](https://docs.astral.sh/uv/).

```bash
cd research/two
uv sync
uv run doctor --build      # образы и 8 проверок окружения
uv run stage all           # s00 … s50; или по одной: uv run stage s20
uv run pytest              # проверка статистики
```

`doctor` проверяет не «запустилось», а «выдало ожидаемые числа»: JPlag на
[фикстурах](fixtures/README.md) (`1.0` на переименовании, `0.0` на чужом
коде), совпадение шага 1 с `structsim.semgrep.dump_ast` и `COMBINED = 1.0`
для одного алгоритма на Java и Python.

Время на 8 ядрах: s00 — полминуты, s10 — 22 мин (378 запусков JPlag), s20 —
27 мин (31 770 пар × 2 версии), s30–s50 — около 3 мин. Стадии идемпотентны:
готовое в `work/` не пересчитывается.

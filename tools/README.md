# tools

Инструменты, которые сравнивают код. Каждый лежит в своём каталоге целиком:
образ с прибитой версией, документация, а если инструмент наш — то и код с
тестами.

| | |
|---|---|
| [`jplag/`](jplag/README.md) | **внешний.** Baseline: поиск плагиата по Greedy String Tiling, один язык |
| [`structsim/`](structsim/README.md) | **наш.** Структурное сходство программ, в том числе между языками |
| `docker-compose.yml` | сборка образов обоих |

Разница между ними принципиальна. **JPlag** мы не разрабатываем: прибиваем
версию, документируем проверенное поведение и используем как меру, с которой
сравниваемся. **structsim** — наш метод: у него есть код, тесты и четыре шага,
и Semgrep входит в него как шаг 1, а не стоит рядом отдельным инструментом.

Инструмент лежит здесь, а не внутри того, кто его вызывает, потому что ни
одному вызывающему он не принадлежит. Вызывающий — исследование или
[`core/`](../core/README.md) — прибивает у себя версию, на которой получил
свои числа, но инструмент от него не зависит и ничего о нём не знает.

## Сборка образов

```bash
docker compose -f tools/docker-compose.yml build
```

Собирается два образа: JPlag для baseline и Semgrep для шага 1 метода.
Запускаются они не через compose, а из кода: каждому прогону нужны свои
монтирования и аргументы.

## Правила

1. **Версия прибита** в Dockerfile, и где возможно — контрольной суммой
   артефакта. Иначе результат невоспроизводим.
2. **Каталог инструмента самодостаточен**: образ, документация и код лежат
   вместе и переносятся целиком. Инструмент не знает о том, кто его
   запускает.
3. **«Запустился» и «сработал» — разные вещи.** Проверять инструмент надо
   входом, ответ для которого известен заранее. Разница не теоретическая:
   JPlag на образе без JDK запускается нормально и молча не разбирает ни
   одного файла, а Semgrep пропускает файл, который не смог разобрать, не
   падая при этом.
4. **Документация — проверенные команды и настоящий вывод**, а не пересказ
   официальной. Если число получено на входе, которого в репозитории нет, это
   должно быть сказано.
5. **Читать начинают с README каталога.** Если инструмент сложнее одного
   образа, README — это карта: что где лежит и куда идти дальше, а не
   пересказ всего подряд.

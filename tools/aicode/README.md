# aicode

Локальная эвристическая проверка исходного кода на AI-похожие фрагменты.
Модель возвращает интервалы символов и confidence; CLI показывает диапазоны
строк и долю отмеченных символов. Это **не** доказательство авторства и не
оценка вероятности происхождения всего файла.

## Как запустить

Обычно используется Docker-образ с уже упакованной квантованной моделью:
CPU, без GPU, укладывается в 5 GB RAM (весам нужно ~4.6 GB распакованной
памяти, ещё ~0.7 GB занимают переходные буферы float32).

```bash
docker run --rm --memory=5g -v "<каталог с кодом>:/work:ro" \
    integritylens/aicode:0.1.1 /work
```

Аргумент — файл или каталог с `.java` (каталог обходится рекурсивно,
`node_modules`, `vendor`, `build` и служебные каталоги пропускаются). Полезные
флаги: `--json` — машинно-читаемый отчёт; `--threshold X` — минимальный
confidence спана (по умолчанию 0.8). Время: ≈6 секунд на загрузку модели
и ≈18–20 секунд на файл в ~40 строк (CPU i7-12700H без GPU, Docker
Desktop/WSL2); до перехода на float32-вычисления тот же прогон занимал
≈2.5 минуты на загрузку и ≈90 секунд на файл.

Если образ ещё не собран — один раз получите артефакты модели и соберите
образ. Быстрее всего скачать готовые артефакты из pinned-релиза (~1.6 GB;
нужен любой Python 3, без зависимостей и без venv):

```bash
(cd tools/aicode && python fetch_model.py)
docker compose -f tools/docker-compose.yml build aicode
```

Скрипт сверяет sha256 архива, распаковывает его в
`tools/aicode/artifacts/gigacheck-int2` и пропускает скачивание, если
артефакты уже на месте. Альтернатива — собрать артефакты локально из
исходного checkpoint (~14 GB скачивания; пути загрузок при этом записываются
в `artifacts/gigacheck-int2.downloads.txt`): команды — в разделе
«Экспорт и сборка образа». Сборка образа модель из сети не качает.

## Что на выходе

Текстовый отчёт: по каждому файлу `FLAGGED` — процент символов, попавших в
найденные фрагменты, и список `lines N-M: confidence C` — найденные фрагменты
с уверенностью модели. `FLAGGED` — не общая уверенность для файла. Если
фрагментов нет — при выбранном пороге модель ничего не отметила.

Проверенный прогон на валидационном датасете `research/dataset/ai` (16

## Экспорт и сборка образа

По умолчанию модель скачивается и квантуется заранее, на машине сборки, а
Docker-образ собирается из готовых файлов и модель из сети не скачивает.
Экспорт требует Python 3.11+ и `uv` (см. «Установка») и около 14 GB места под
исходный checkpoint; результат пишется в пустой каталог:

```bash
cd tools/aicode
HF_HOME="$PWD/.hf-cache" uv run python -m aicode.export_model --output artifacts/gigacheck-int2
docker compose -f ../docker-compose.yml build aicode
docker run --rm -v /path/to/source:/work integritylens/aicode:0.1.1 /work
```

Экспорт проверяется локально без Docker:

```bash
uv run aicode src --model artifacts/gigacheck-int2 --local-files-only
```

Загрузка таких артефактов использует C++-опы Quanto над упакованными весами:
на Linux расширение собирается при сборке образа из установленного `g++`, а на
Windows локальный запуск без MSVC Build Tools падает на компиляции расширения —
на этой платформе проверяйте экспорт через Docker-образ.

Все пути, куда экспорт что-то скачал, записываются в файл
`artifacts/gigacheck-int2.downloads.txt`: исходный checkpoint попадает в кэш
Hugging Face, и без этого файла его легко потерять из виду. Каждая строка
манифеста — полный путь; после проверки экспорта скачанное из кэша можно
удалить. Если путь до домашней папки содержит не-ASCII символы (например,
кириллицу в имени пользователя Windows), sentencepiece не откроет файлы
токенизатора из такого кэша — поэтому в командах выше задан `HF_HOME` с путём
без них; этот каталог тоже попадает в манифест.

Чтобы собрать образ из другого каталога артефактов, задайте `AICODE_MODEL_DIR`
(путь внутри `tools/aicode`, по умолчанию `artifacts/gigacheck-int2`).
Контейнер запускается офлайн с уже включённым checkpoint; до сервера нужно
передать готовый образ (например, опубликовать его в registry или перенести
через `docker save` / `docker load`). Сборка проверяет, что скопированные веса
загружаются, — образ с испорченным экспортом не соберётся. Режим квантования
записан внутри артефактов (`aicode_model.json`), поэтому отчёт показывает
фактический режим без дополнительных переменных окружения.

Для компромисса между размером и качеством экспортируйте int4-вариант и
соберите его:

```bash
uv run python -m aicode.export_model --output artifacts/gigacheck-int4 --quantization int4
AICODE_MODEL_DIR=artifacts/gigacheck-int4 docker compose -f ../docker-compose.yml build aicode
```

Если экспорт на машине сборки невозможен, остался вариант, при котором модель
скачивается и квантуется прямо при сборке образа (тогда Python и `uv` на хосте
не нужны). В этом режиме пути загрузок в манифест не попадают: файлы оседают
в кэше сборки Docker, который освобождается через `docker builder prune`.

```bash
docker build -f tools/aicode/aicode.Dockerfile --target image-hub \
    -t integritylens/aicode:0.1.1 tools/aicode
# для int4 добавьте --build-arg AICODE_QUANTIZATION=int4
```

### Готовые артефакты из релиза

Чтобы не экспортировать модель на каждой машине, артефакты выложены ассетом
релиза [`aicode-model-v0.1.0`](https://github.com/ITMO-Red-Team/IntegrityLens/releases/tag/aicode-model-v0.1.0)
— `gigacheck-int2.zip`, 1.59 GB,
sha256 `afd7277e650d08055c6deca54375dabc8423cdc289405b9c08343058a750c28c`.
`fetch_model.py` — standalone-скрипт на стандартной библиотеке Python: он
скачивает архив, сверяет сумму при загрузке и распаковывает в
`artifacts/gigacheck-int2` (флаги: `--force`, `--url`, `--sha256`, `--output`).
Артефакты из релиза и артефакты локального экспорта взаимозаменяемы: сборка
образа устроена одинаково.

Сопровождающим — выпуск нового релиза артефактов: упаковка должна
воспроизводить layout «один каталог верхнего уровня с файлами модели», а
после упаковки нужно обновить `ARTIFACT_SHA256` в `fetch_model.py` и сумму в
этом README. Перезапакованный без обновления суммы архив не пройдёт проверку:

```bash
cd tools/aicode/artifacts
python -m zipfile -c gigacheck-int2.zip gigacheck-int2
gh release create aicode-model-v0.2.0 gigacheck-int2.zip \
    --title "aicode model artifacts v0.2.0" \
    --notes "Quantized GigaCheck-Detector-Multi (int2) artifacts for tools/aicode."
```

Сам zip в git не хранится: он лежит в игнорируемом `artifacts/` и исключён из
build context через `.dockerignore`.

## Установка (для запуска без Docker)

Нужны Python 3.11+, `uv` и доступ в интернет для установки зависимостей и
первого скачивания checkpoint. Сначала установите CPU-only зависимости:

```bash
cd tools/aicode
uv sync
uv pip install --no-deps "git+https://github.com/ai-forever/gigacheck.git@8cdbe6a1ce628b49b4aa0794edf7a425a47a774c"
```

Для `torch` в `pyproject.toml` закреплена версия 2.7.1 из официального CPU
индекса PyTorch. Пакет `gigacheck` ставится без его полного набора зависимостей
для обучения: inference использует только объявленные здесь библиотеки.

```bash
uv run aicode src/main.py
uv run aicode src
uv run aicode src --json --output report.json
uv run aicode src --threshold 0.9 --quantization int4
uv run aicode src --quantization none --dtype float32
```

`--quantization int2` — значение по умолчанию и самый экономный по памяти
режим. `int4` уменьшает потери качества, но не подходит как гарантия запуска в
5 GB RAM. При обычном запуске quantization применяется при загрузке весов на
CPU; исходный checkpoint и его кэш на диске остаются около 14 GB.
`--quantization none` отключает PTQ.

Если вы повторно запускаете `uv sync`, после него снова установите runtime-пакет
`gigacheck`: он намеренно не входит в зависимости обучения upstream-проекта.

Модель можно заранее скачать и затем работать без доступа к сети:

```bash
uv run aicode src
uv run aicode src --local-files-only
```

При не-ASCII пути домашней папки (см. «Экспорт и сборка образа») и этот запуск
требует `HF_HOME` без таких символов; где именно осели скачанные файлы, проще
всего проверить через манифест экспорта.

## Модель и ограничения

По умолчанию используется
[`iitolstykh/GigaCheck-Detector-Multi`](https://huggingface.co/iitolstykh/GigaCheck-Detector-Multi)
(Apache-2.0), закреплённая на ревизии
`9fabe1503f99cc8a6f639996f9475c3ec19bc067`. Модель обучалась на обычном тексте
(датасет LLMTrace, английский и русский), а не на исходниках: результаты для
кода — только ориентир, который нужно проверять человеком.

Это Mistral 7B: исходный checkpoint занимает около 14 GB. По умолчанию веса
квантуются при загрузке с помощью post-training quantization (Quanto int2);
это резко снижает потребление RAM и рассчитано на сервер с 5 GB RAM. Из-за
служебных данных, ОС и временных активаций фактический расход зависит от
системы. CPU-инференс может быть медленным, а int2 заметно ухудшает качество.
`--quantization int4` сохраняет больше качества, но требует больше памяти;
`--quantization none` отключает квантизацию и требует не менее 16 GB RAM
(рекомендуется 24 GB и больше).

Скорость на CPU: линейные слои квантованной модели по умолчанию считаются в
float32 (`AICODE_COMPUTE=float32`, отключение — `bfloat16`). На процессорах
без AVX512_BF16/AMX bfloat16-GEMM в PyTorch эмулируется и в 4–5 раз медленнее;
float32-умножения идут нативным AVX2-путём, активации между слоями остаются в
bfloat16, де квант весов — прямой в float32 (точность не ниже прежней bf16,
замеры: 6 работ по 1.2–1.6 КБ — 531 с в bf16 на 4 потоках против 108 с в
float32 на 16 потоках). Число потоков задаёт вызывающая сторона: CLI использует
умолчание torch (половина логических ядер), воркер — `AICODE_THREADS`.
Байтовый вывод воспроизводим при том же числе потоков; на другом числе
фрагменты сдвигаются на единицы байт (до ~1 п.п. flagged на пробах), порог
отсечения эти сдвиги не замечает.

Файл разбивается на окна до 900 токенов, чтобы анализировать и длинные файлы,
а интервалы модели переводятся обратно в строки исходника.

Проверенное качество (см. прогон выше): карта модели рекомендует fp32 и порог
0.5, но полностью fp32-веса требуют ~28 GB RAM и несовместимы с лимитом 5 GB;
текущий режим считается в float32 только в GEMM при int2-весах. На
неквантованной модели и при переносе DETR-головы в fp32 вероятности спанов не
восстанавливаются — уверенность детекций в этой конфигурации не доходит ни до
0.5, ни до 0.8. Перспективное направление — классификационная голова модели
(файловая оценка «AI / человек»): в отдельных пробах на Java она выдавала
0.83–0.91, на AI-прозе 0.48–0.73. Но её классы сейчас не интерпретируемы:
`id2label` в конфигурации checkpoint отсутствует, и какой индекс означает
«AI», нужно сначала подтвердить по обучающему датасету.

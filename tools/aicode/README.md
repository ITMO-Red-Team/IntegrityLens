# aicode

Локальная эвристическая проверка исходного кода на AI-похожие фрагменты.
Модель возвращает интервалы символов и confidence; CLI показывает диапазоны
строк и долю отмеченных символов. Это **не** доказательство авторства и не
оценка вероятности происхождения всего файла.

## Модель и ограничения

По умолчанию используется
[`iitolstykh/GigaCheck-Detector-Multi`](https://huggingface.co/iitolstykh/GigaCheck-Detector-Multi)
(Apache-2.0), закреплённая на ревизии
`9fabe1503f99cc8a6f639996f9475c3ec19bc067`. Модель обучалась на обычном тексте,
а не на исходниках: результаты для кода — только ориентир, который нужно
проверять человеком.

Это Mistral 7B: исходный checkpoint занимает около 14 GB. По умолчанию веса
квантуются при загрузке с помощью post-training quantization (Quanto int2);
это резко снижает потребление RAM и рассчитано на сервер с 4 GB RAM. Из-за
служебных данных, ОС и временных активаций фактический расход зависит от
системы, поэтому 4 GB не гарантируются на каждой конфигурации. CPU-инференс
может быть медленным, а int2 заметно ухудшает качество. `--quantization int4`
сохраняет больше качества, но требует больше памяти; `--quantization none`
отключает квантизацию и требует не менее 16 GB RAM (рекомендуется 24 GB и
больше). Для CPU без эффективной поддержки bfloat16 используйте
`--dtype float32` ценой дополнительной памяти.

Файл разбивается на окна до 900 токенов, чтобы анализировать и длинные файлы,
а интервалы модели переводятся обратно в строки исходника. Поддерживаются
обычные файлы кода с известными расширениями; `node_modules`, `vendor`,
`build`, `dist` и служебные каталоги пропускаются.

## Установка

Нужны Python 3.11+, `uv` и доступ в интернет для установки зависимостей и
первого скачивания checkpoint. Сначала установите CPU-only зависимости:

```bash
cd tools/aicode
uv sync
uv pip install --no-deps "git+https://github.com/ai-forever/gigacheck.git@8cdbe6a1ce628b49b4aa0794edf7a425a47a774c"
```

Для `torch` в `pyproject.toml` закреплена версия 2.7.1 из официального CPU
индекса PyTorch. Пакет `gigacheck` ставится без его полного набора зависимостей
для обучения: inference использует только объявленные здесь библиотеки.

## Запуск

```bash
uv run aicode src/main.py
uv run aicode src
uv run aicode src --json --output report.json
uv run aicode src --threshold 0.9 --quantization int4
uv run aicode src --quantization none --dtype float32
```

### Быстрая ручная проверка одного файла

После сборки Docker-образа положите файл `example.py` в текущий каталог и
запустите (команда работает в PowerShell и bash):

```bash
docker run --rm -v "${PWD}:/work" integritylens/aicode:0.1.0 /work/example.py
```

В выводе найдите `lines N-M` — найденный фрагмент, и `confidence X.XXX` —
уверенность модели для этого фрагмента. `FLAGGED` — процент символов файла,
попавших в найденные фрагменты; это не общая уверенность для файла. Если
фрагментов нет, при выбранном пороге модель ничего не отметила. Например,
чтобы получить машинно-читаемый отчёт:

```bash
docker run --rm -v "${PWD}:/work" integritylens/aicode:0.1.0 /work/example.py --json
```

Либо без Docker, из `tools/aicode`, после установки зависимостей и runtime-пакета:

```bash
uv run aicode example.py
```

`--quantization int2` — значение по умолчанию и самый экономный по памяти
режим. `int4` уменьшает потери качества, но не подходит как гарантия запуска в
4 GB RAM. При обычном запуске quantization применяется при загрузке весов на
CPU; исходный checkpoint и его кэш на диске остаются около 14 GB.
`--quantization none` отключает PTQ.

Если вы повторно запускаете `uv sync`, после него снова установите runtime-пакет
`gigacheck`: он намеренно не входит в зависимости обучения upstream-проекта.

Модель можно заранее скачать и затем работать без доступа к сети:

```bash
uv run aicode src
uv run aicode src --local-files-only
```

### Локальный экспорт и Docker

Чтобы не скачивать полный исходный checkpoint на целевой сервер, экспортируйте
квантизованную модель на машине сборки:

```bash
uv run python -m aicode.export_model --output artifacts/gigacheck-int2
uv run aicode src --model artifacts/gigacheck-int2 --local-files-only
```

Экспорт требует около 14 GB свободного места для исходных весов и места для
результата; процесс загрузит checkpoint с указанной ревизии и сохранит
Quanto-веса вместе с конфигурацией и токенизатором. Каталог результата должен
быть пустым. Для Docker используйте:

```bash
docker compose -f tools/docker-compose.yml build aicode
docker run --rm -v /path/to/source:/work integritylens/aicode:0.1.0 /work
```

Сборка образа скачивает модель только на build host. Контейнер запускается
офлайн с уже включённым checkpoint; до сервера нужно передать готовый образ
(например, опубликовать его в registry или перенести через `docker save` /
`docker load`). По умолчанию в образ упаковывается int2, размер которого
зависит от формата сохранённых весов и зависимостей. Для int4:

```bash
AICODE_QUANTIZATION=int4 docker compose -f tools/docker-compose.yml build aicode
```

Если запускаете собранный образ вне Docker Compose, задайте
`AICODE_QUANTIZATION=int4` при запуске int4-образа, чтобы отчёт показывал
фактический режим квантования.

JSON содержит модель, ревизию и режим квантизации, путь к файлу,
`flagged_percent` (доля символов, попавших хотя бы в один обнаруженный интервал)
и spans с диапазоном символов, строк и confidence. Это **не** вероятность,
что весь файл написан AI.

## Проверки

Быстрые тесты не загружают модель и не требуют сети:

```bash
uv run pytest
```

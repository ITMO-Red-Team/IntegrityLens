# structsim

**Структурное сходство программ.** Берёт программы и для каждой пары выдаёт
число от 0 до 1: чем больше, тем похожее они устроены — в том числе если
программы написаны на разных языках.

Сравнивается: ветвления, циклы и их вложенность, порядок операций, работа с
данными. Не учитывается: имена переменных, оформление и язык.

> Число говорит о сходстве **реализации**, а не алгоритма. Один алгоритм,
> записанный по-разному, может получить низкую оценку, а разные алгоритмы с
> похожим кодом — заметную.

> **Восемь языков из девяти сходятся буква в букву.** Один алгоритм на
> Python, C++, C#, Go, Java, JavaScript, Kotlin и Swift даёт одну и ту же
> последовательность меток и `COMBINED` ровно 1.000; это проверяется тестами.
> У Rust расходится одна метка из двадцати шести — неявный возврат. Важно
> помнить, что такие расхождения **не ломают запуск**, а молча снижают
> оценку: [docs/step2.md](docs/step2.md#сходимость-языков-проверяется-отдельно-для-каждого).

## Как запустить

Нужен Docker: шаг 1 работает в контейнере.

```bash
docker compose -f tools/docker-compose.yml build semgrep
cd tools/structsim
uv sync
uv run structsim <директория с решениями одной задачи>
```

Вывод — пары, самые похожие сначала:

```
разобрано программ: 5, пар: 10, пропущено файлов: 1

пара                              COMBINED   поряд   фрагм   функц  contrast-z
a_py.py ↔ c_translated.go            1.000    1.00    1.00    1.00        1.53
a_py.py ↔ b_cpp.cpp                  0.919    0.96    0.83    0.96        1.15
a_py.py ↔ e_while.java               0.644    0.80    0.33    0.80       -0.11
a_py.py ↔ d_other.py                 0.429    0.60    0.09    0.60       -0.93
```

Здесь `a_py.py` и `c_translated.go` — один алгоритм на Python и на Go, и
оценка 1.000: после очистки их последовательности совпадают буква в букву.
`b_cpp.cpp` тот же алгоритм на C++, но с лишним параметром. `e_while.java`
решает ту же задачу через `while`, `d_other.py` — другую задачу.

Какие именно куски совпали — отдельной командой, **с диапазонами строк**:

```bash
uv run structsim <директория> --tiles a_py.py c_translated.go
```

```
общие куски a_py.py ↔ c_translated.go (порог 10 меток):

  a_py.py строки 1–6 ↔ c_translated.go строки 1–8 — 26 меток
    FUNC P1 ; ID = N0 LOOP IF ID IDX ID > N0 ; ID = ID + ID IDX ID END END RET ID END
```

| Ключ | Зачем |
|---|---|
| `--top N` | сколько пар показать (по умолчанию 10) |
| `--tiles A B` | общие куски этой пары, строками исходника |
| `--min-tile N` | минимальная длина куска в метках |
| `--csv файл` | оценки всех пар в файл |

Все программы в директории должны решать **одну задачу**: `contrast-z` считает
фон по набору, и на смеси задач он бессмыслен. Набор меньше пяти программ —
`contrast-z` не считается, остальное считается.

## Четыре шага

| | Шаг | Что делает | Где |
|---|---|---|---|
| 1 | общее дерево | `semgrep-core` разбирает файл в дерево, одинаковое для разных языков | [`semgrep.py`](src/structsim/semgrep.py) |
| 2 | очистка | дерево → последовательность меток, без имён, типов и значений | [`labels.py`](src/structsim/labels.py) |
| 3 | сравнение пары | три меры, итог `COMBINED` | [`compare.py`](src/structsim/compare.py) |
| 4 | сравнение с фоном | `contrast-z` по набору решений одной задачи | [`contrast.py`](src/structsim/contrast.py) |

Плюс отдельный вывод: **тайлы** — какие куски двух программ совпали
([`tiles.py`](src/structsim/tiles.py)). На оценку не влияют.

**Как это связано между собой — [docs/pipeline.md](docs/pipeline.md).** Там
схема, что откуда вызывается и какие данные идут между шагами.

## Тесты

```bash
uv run pytest            # быстрые, меньше секунды
uv run pytest -m docker  # те, которым нужен собранный образ
```

Быстрые не требуют Docker: шаги 2–4 — чистые функции, а деревья для них лежат
в [`tests/data`](tests/data/README.md). Главная проверка шага 2 — совпадение с
последовательностью, разобранной в документе о методе, сразу на C++ и на
Python.

## Устройство

```
tools/structsim/
  README.md
  pyproject.toml            — uv-проект, ядро без зависимостей
  docker/
    semgrep.Dockerfile      — образ для шага 1
  docs/                     — конвейер и шаг 1
  src/structsim/
    semgrep.py              — шаг 1: файл → дерево
    labels.py               — шаг 2: дерево → метки и блоки
    compare.py              — шаг 3: три меры и COMBINED
    contrast.py             — шаг 4: contrast-z
    tiles.py                — общие куски (GST)
    model.py                — Program, Block, Tile, Span
    analyze.py              — конвейер целиком
    cli.py                  — командная строка
  tests/
    data/                   — выгрузки semgrep-core для тестов
```

Ядро намеренно **без зависимостей**: шаги 2–4 — это обход дерева и арифметика
над последовательностями. Единственная внешняя часть — Semgrep, и он
запускается в контейнере, а не импортируется.

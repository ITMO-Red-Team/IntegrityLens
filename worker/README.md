# Воркеры

Один образ обслуживает оба метода; метод задаёт `WORKER_METHOD`.
Воркер забирает задание из PostgreSQL, скачивает исходники из S3 и запускает
[core](core/CONTRACT.md) отдельным процессом.

Задания захватываются через `FOR UPDATE SKIP LOCKED`. Истёкшая аренда допускает повтор;
запись результата проверяет владельца и номер попытки. Результат проходит проверку схемы
и полноты пар, загружается в `runs/{runId}/attempt-{n}/`, затем фиксируется в БД.

## Моки

`MOCK_DELAY_SECONDS` задаёт задержку, `CORE_TIMEOUT_SECONDS` — таймаут core.
`MOCK_SCENARIO` выбирает сценарий для новых прогонов/попыток:

| Сценарий | Результат |
| --- | --- |
| `success` | Все работы разобраны |
| `partial` | Одна работа не разобрана |
| `fail_once` | Первая попытка падает, повтор успешен |
| `tool_error` | Все попытки падают |
| `invalid_input` | Ошибка без повторов |

[Интеграционные тесты очереди](../infra/README.md#проверки).

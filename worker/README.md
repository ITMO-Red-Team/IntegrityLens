# worker

Python 3.12. Один образ для `worker-jplag` и `worker-structsim`; метод задаётся через `WORKER_METHOD`.
Воркер общается с PostgreSQL и MinIO, запускает только `core` в отдельном процессе. ZIP проверяет API;
воркер скачивает уже нормализованные исходники.

Задание забирается атомарно через `FOR UPDATE SKIP LOCKED`, опрос раз в 2 секунды. Heartbeat обновляется
раз в 15 секунд. После 2 минут без heartbeat задание доступно другому воркеру. Максимум три попытки,
таймаут процесса — 600 секунд. Код core `1` допускает повтор, `2` завершает прогон сразу.
Изменения heartbeat, ошибок и результата проверяют владельца, номер попытки и статус. Устаревшая
попытка не может перезаписать результат новой. SIGTERM завершает дочерний процесс; незавершённая аренда истечёт.

`result.json` проверяется по JSON Schema и правилам полноты пар, затем вместе с артефактами загружается
в `runs/{runId}/attempt-{n}/`. В БД результат и статус `done` записываются одним запросом.
Логи JSON содержат `batchId` и `runId` для операций прогона; текст исходников не логируется.

Настройки:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `MOCK_DELAY_SECONDS` | `2` | Задержка мок-анализа |
| `MOCK_SCENARIO` | `success` | Сценарий ниже |
| `CORE_TIMEOUT_SECONDS` | `600` | Таймаут процесса core |

Сценарии: `success`; `partial` — одна работа не разобрана; `fail_once` — первая попытка падает, вторая
успешна; `tool_error` — все три попытки падают; `invalid_input` — ошибка без повторов.
Сценарии не выбираются случайно. Изменение настройки влияет только на новые прогоны/попытки.

# Воркеры

Движок AI с отдельным файловым контрактом и образом описан в
[ai/README.md](ai/README.md). Его адаптер очереди подключается отдельно.

По образу на метод: `jplag` и `structsim` из одного [Dockerfile](Dockerfile). Метод задаёт
`WORKER_METHOD`. Воркер забирает задание из PostgreSQL, скачивает исходники из S3 и запускает
[core](core/CONTRACT.md) отдельным процессом. Функции из набора
[шаблонных алгоритмов](core/CONTRACT.md#шаблонные-алгоритмы) при сравнении не учитываются.

Очередь опрашивается раз в 2 с, задания захватываются через `FOR UPDATE SKIP LOCKED`. Истёкшая аренда допускает повтор;
запись результата проверяет владельца и номер попытки. Результат проходит проверку схемы
и полноты пар, загружается в `runs/{runId}/attempt-{n}/`, затем фиксируется в БД.

Core работает в своей группе процессов и по `CORE_TIMEOUT_SECONDS` (600 с) или при потере
аренды гасится целиком, вместе с JVM и `semgrep-core`. Таймаут — ошибка без повторов: тот же
вход не уложится и в следующий раз. Время этапов (поле `timings`) и stderr core пишутся в журнал,
[замеры, асимптотика и что оптимизировано](bench/README.md) — отдельно.

Сборка каждого образа заканчивается проверкой на входе с известным ответом: на JRE вместо
JDK или с поехавшим форматом Semgrep образ просто не соберётся.

## Моки

`CORE_ENGINE=mock` заменяет настоящие методы моком, по умолчанию `real`. При `real` параметры
мока в самом прогоне — ошибка без повторов.
`MOCK_DELAY_SECONDS` задаёт задержку. `MOCK_SCENARIO` выбирает сценарий для новых прогонов/попыток:

| Сценарий | Результат |
| --- | --- |
| `success` | Все работы разобраны |
| `partial` | Одна работа не разобрана |
| `fail_once` | Первая попытка падает, повтор успешен |
| `tool_error` | Все попытки падают |
| `invalid_input` | Ошибка без повторов |

[Интеграционные тесты очереди](../infra/README.md#проверки).

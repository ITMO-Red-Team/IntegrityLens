# Как воркер AI считает оценки

Задание, результат, формулы и детерминизм. Общий контракт воркеров — в
[docs/contracts.md](../../../docs/contracts.md#контракты-воркеров), сама
модель — в [tools/aicode](../../../tools/aicode/README.md), быстрый старт —
в [README](../README.md).

## Задание и результат

Задание — `{contract, runId, methodVersion, params, inputFiles[{submissionId, path}]}`, путь
относительно рабочего каталога. Результат — ровно один `{submissionId, status, score, suspicious,
reason?}` на входной файл: ошибки отдельных файлов не валят прогон, `done` их допускает.

Так выглядит результат оценки работы `student_02` из образцового архива
(`submissionId` опущен, `score` округлён):

```json
{"contract": "integritylens.ai/1", "runId": "…",
 "methodVersion": "aicode-0.1.1+gigacheck-9fabe1503f+int2", "params": {"threshold": 0.05},
 "files": [{"submissionId": "…", "status": "ok", "score": 0.5411,
            "suspicious": [{"startIndex": 654, "endIndex": 1425, "confidence": 0.21419790387153625}]}]}
```

Оценки шести работ того же прогона — 0.4638, 0.5366, 0.4811, 0.5193, 0.4949,
0.4560 (до перехода на float32-GEMM и 16 потоков тот же архив давал 0.4538,
0.5323, 0.4676, 0.5118, 0.4910, 0.4543 — сдвиг до ~1.5 п.п., число фрагментов
то же).

## Откуда берутся поля

| Контракт | Откуда берётся |
| --- | --- |
| `score` всей работы | доля помеченных байтов: сумма слитых фрагментов / размер файла |
| `suspicious[].startIndex/endIndex` | байтовые смещения UTF-8 с 0, правая граница исключена; aicode отдаёт символьные — конвертация с учётом BOM (+3 байта) и переводов строк |
| `suspicious[].confidence` | уверенность интервальной головки; у слитых пересекающихся фрагментов — максимум |
| `reason.code` | `NOT_PARSED` — не читается или не UTF-8, `TOOL_ERROR` — сбой инференса |

## Переводы строк

Переводы строк приводятся к `\n` до модели (`\r\n` и `\r`), как это делает
текстовый режим, которым читает файл сам aicode. Модель знает только `\n`: с
`\r` её уверенность падает, и слабый сигнал не проходит порог. Замер на одной
учебной работе: с LF — 0.4676, с CRLF — 0.0000, фрагментов выше порога нет.
Смещения при этом остаются в байтах исходного файла.

## Порог

Порог — параметр прогона `params.threshold`, по умолчанию `0.05`. Умолчание
инструментальной карточки (0.8) на int2-кванте не пересекается ни одним
confidence на реальном коде (максимум ~0.53), то есть даёт пустые
`suspicious`; 0.05 даёт сигнал, но шумный — подробности и замеры в
[tools/aicode/docs/how-it-works.md](../../../tools/aicode/docs/how-it-works.md).
Модель фильтрует интервалы строго `> threshold` — порог 0 отсекает и нулевые
уверенности.

## methodVersion

`methodVersion` вида `aicode-0.1.1+gigacheck-9fabe1503f+int2` собирается из
версии пакета aicode и метаданных артефакта (`aicode_model.json`), попадает в
задание и результат и сверяется движком: образ с одной версией модели не
обработает задание под другую (ошибка без повторов). Вместе с результатом в
`runs` сохраняются `method_version` и фактически применённые `params`.

## Детерминизм

Детерминизм (одинаковые файлы, версия и параметры — одинаковые оценки): число
потоков torch задано в образе (`AICODE_THREADS`, по умолчанию 16, но не больше
числа ядер машины). Байтовый вывод воспроизводим при одном и том же числе
потоков (самопроверка в образе прогоняет файл дважды в одном процессе); между
разными числами потоков фрагменты сдвигаются на единицы байт — порядок
суммирования в float32-GEMM, до ~1 п.п. flagged на пробах, число фрагментов не
меняется.
